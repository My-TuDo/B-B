# 接口契约

> **写入规则**：只有 `status: locked` 的阶段（人测试完全通过后）才能将其公开接口写入此文件。
>
> **读取规则**：后续阶段的需求 md 和主 Agent 的任务书应引用此文件中的接口签名。
>
> **保护规则**：`locked` 状态的接口签名不可变更，只能新增，不能修改或删除。
>
> **内部重构例外**：在不改变 locked 接口签名的前提下，后续阶段可以重写上游包的内部实现。约束：
> - 回归锚点必须全量通过
> - contracts.md 中的接口签名不变（字段名、类型、HTTP 路径、方法不变）
> - 如果必须改接口 → 不是重构，是破坏性变更 → 必须新增 `/v2/` 端点或新字段名，旧接口保留至下阶段废弃
>
> **向后兼容扩展**：以下操作视作兼容扩展，允许，不算回归：
> - 响应体新增可选字段
> - 新增 API 端点
> - 已有包新增导出函数（不修改已有函数签名）
> - 数据库表新增可空列（不修改已有列类型、不删除已有列）
>
> **禁止操作**：
> - 删除或重命名已有响应字段
> - 修改已有 API 端点的 HTTP 方法或路径
> - 修改已有导出函数的参数或返回值类型
> - 修改已有数据库列类型、删除已有列
